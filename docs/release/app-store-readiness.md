# App Store and native beta readiness

This is a bounded readiness record for the Expo SDK 54 client. It documents repository configuration and release work still required; it does not claim an App Store submission, hardware validation, or legal review.

## In place

- App display name is KinetiQ; iOS and Android identifiers are `io.kinetiq.app`.
- Auth0 callback scheme remains `rimready`. Keep the app config and Auth0 allowlist synchronized.
- Expo ImagePicker is configured with video/photo library and camera purpose strings. `microphonePermission: false` follows the [SDK 54 ImagePicker configuration](https://docs.expo.dev/versions/v54.0.0/sdk/imagepicker/): the generated Android manifest removes `RECORD_AUDIO`, and the checked iOS Info.plist has no microphone usage string.
- Splash and Android adaptive icon backgrounds use the configured warm-neutral/dark colors.
- `eas.json` has development, internal preview, and store production profiles. No EAS project ID, store credentials, or signing secrets are included.

## Release gates

1. **Identifiers and Auth0:** Create or confirm the store records for `io.kinetiq.app`; add the exact native Auth0 callback URL(s) generated by this scheme to Allowed Callback URLs for the production Auth0 application; test sign-in, refresh, and sign-out on a signed device build. Do not change `rimready` independently of that allowlist.
2. **API and service:** Set `EXPO_PUBLIC_KINETIQ_API_URL` to the deployed HTTPS endpoint in release configuration. Confirm API availability, TLS certificate validity, Auth0 production configuration, and supported-device network access. The repository's old private-network HTTP URL is not suitable for release.
3. **Privacy disclosures and policies:** Have the operator complete and review the privacy policy, terms if applicable, Apple privacy nutrition labels, Google Play Data safety disclosures, and permission/data-use statements based on the actual deployed services and SDK behavior. This repository does not assert legal compliance or supply final policy text.
4. **Account deletion:** The in-app flow creates or cancels an authenticated deletion request for operator processing. It does not delete app data, the backend identity record, or the Auth0 identity; all remain in place, including when a request is pending or canceled. Before release, define and staff the separate operator workflow for processing requests, including app data and stored media, Auth0 identity, retention exceptions, and support escalation. Do not represent submitting a request as completed deletion.
5. **Capture and runtime:** Validate video selection and camera recording on current supported iOS and Android physical devices, including permission denial, revocation, orientation, file size/duration limits, upload retry, and deletion. Check app startup, navigation, secure token persistence, and 3D/runtime behavior on the actual minimum supported devices. Browser preview and Expo config alone do not establish native camera, GPU/3D, or performance support.
6. **Analysis claims:** Validate every biomotion/biomechanics claim against representative recordings and qualified review. Clearly disclose current limits, quality failures, supported sports/movements, and that feedback is not a medical diagnosis. Do not present unvalidated measurements as clinical or definitive outcomes.
7. **Store readiness:** Purchase/activate Apple Developer Program membership and configure App Store Connect signing, provisioning, privacy and age-rating metadata, screenshots, support/contact details, and review notes. Configure Google Play Console ownership, signing, Data safety, and release metadata if Android distribution is planned. Produce signed beta artifacts and collect device/tester evidence before release approval.
